# Ручная проверка. Этап 1 «Скелет бота»

Что проверяем: бот запускается на твоём компьютере, отвечает на `/start` и `/help` в Telegram,
пишет логи в файл и не разваливается, если токен забыли вписать.

Займёт минут 15. Иди строго по пунктам сверху вниз. Команды вводятся в **PowerShell**
(клавиша Win → набрать `powershell` → Enter). Команду можно скопировать и вставить
правой кнопкой мыши.

Если на macOS или Linux — команды те же, отличаются только две строки, они помечены отдельно.

---

## Часть 1. Подготовка

### 1. Открой папку проекта

```powershell
cd путь\к\tg-schedule-bot
```

Вместо `путь\к\` подставь, куда скачан проект. Например: `cd C:\Users\Таня\tg-schedule-bot`.

**Должно получиться:** в начале строки PowerShell появился путь, заканчивающийся на
`tg-schedule-bot`.

### 2. Получи токен бота у @BotFather (если ещё не получал)

1. В Telegram в поиске найди **@BotFather** (с синей галочкой).
2. Отправь ему `/newbot`.
3. Придумай имя бота — любое, например `Будильник 4-МД-4`.
4. Придумай username — латиницей и обязательно с окончанием `bot`, например `md4_wakeup_bot`.
   Если такой уже занят, BotFather попросит другой.
5. В ответ придёт длинная строка вида `8123456789:AAF-xxxxxxxxxxxxxxxxxxxxxxxxxxx`. Это **токен**.

**Должно получиться:** есть сообщение от BotFather со строкой, где до двоеточия цифры,
а после — буквы и цифры. Никому её не показывай.

Если токен уже был получен раньше — пропусти пункт. Если потерял — напиши BotFather `/mybots`,
выбери своего бота → `API Token`.

### 3. Создай файл настроек `.env`

```powershell
copy .env.example .env
notepad .env
```

(на macOS/Linux: `cp .env.example .env`, затем `nano .env`)

Откроется Блокнот. В строке `BOT_TOKEN=` сразу после знака `=` вставь токен из пункта 2.
Без пробелов, без кавычек. Должно выглядеть так:

```
BOT_TOKEN=8123456789:AAF-xxxxxxxxxxxxxxxxxxxxxxxxxxx
```

Остальные строки на этом этапе не трогаем — ключи карт понадобятся позже.
Сохрани (Ctrl+S) и закрой Блокнот.

**Должно получиться:** в папке проекта появился файл `.env`. На GitHub он не уедет —
это уже настроено.

### 4. Установи библиотеки

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

(на macOS/Linux вторая строка другая: `source .venv/bin/activate`)

Первая команда создаёт отдельную «коробку» для библиотек проекта, вторая её включает,
третья ставит внутрь всё нужное.

**Должно получиться:** в начале строки PowerShell появилась приписка `(.venv)`,
а установка закончилась строкой `Successfully installed ...` без красного текста.

Если `.venv` уже создавался раньше — первую и третью строки можно пропустить,
достаточно второй.

---

## Часть 2. Автоматические тесты

### 5. Прогони тесты

```powershell
python -m pytest -q
```

**Должно получиться:** последняя строка вида `231 passed in 2.5s` (число тестов растёт
с каждым этапом, важно только слово `passed`). Слова `failed` или `error`
быть не должно (строчка про `PytestDeprecationWarning` — это не ошибка, её можно игнорировать).

Если написано `failed` — скопируй весь вывод целиком и отдай его агенту `debugger`
(как — в пункте 15).

## Часть 3. Живой бот в Telegram

### 6. Запусти бота

```powershell
python -m app
```

**Должно получиться:** в окне появилась строка вида

```
2026-09-03 12:05:00 INFO     app.bot: Бот запущен: @md4_wakeup_bot (id=8123456789)
```

Курсор мигает, новых строк нет — так и надо, бот ждёт сообщений.
**Это окно не закрывай**, пока идёт проверка: закроешь — бот выключится.

Если вместо этого появилась строка со словом «Ошибка» — переходи к пункту 15.

### 7. Найди своего бота в Telegram

В поиске Telegram введи username бота из пункта 2 (например `md4_wakeup_bot`) и открой чат.
Внизу будет кнопка **«Запустить»** / **«Start»**.

**Должно получиться:** чат с ботом открыт.

### 8. Отправь `/start`

Нажми кнопку «Запустить» или напиши в чат `/start`.

**Должно получиться:** в течение 1–2 секунд приходит приветствие, которое начинается словами
«Привет! Я бот-будильник группы 4-МД-4». В тексте есть упоминание `/help`.
Русские буквы нормальные, без «кракозябр» и без значков вроде `<b>`.

### 9. Отправь `/help`

**Должно получиться:** приходит короткий список: `/start — знакомство` и `/help — этот список`,
плюс фраза о том, что расписание и будильник появятся позже.

### 10. Отправь несуществующую команду

Напиши в чат `/погода` (или любую другую выдуманную команду со слэшем).

**Должно получиться:** бот отвечает «Я пока не знаю такой команды. Посмотри /help…».

### 11. Отправь обычный текст

Напиши в чат `привет` (без слэша).

**Должно получиться:** бот **молчит**. Это правильное поведение на этом этапе:
обычные сообщения понадобятся позже, для диалогов настройки.

### 12. Проверь, что всё записалось в лог

Не закрывая окно с ботом, открой **второе** окно PowerShell, перейди в папку проекта
(как в пункте 1) и выполни:

```powershell
notepad logs\bot.log
```

(на macOS/Linux: `open logs/bot.log` или `nano logs/bot.log`)

**Должно получиться:** файл существует, в нём есть строки:

- `Бот запущен: @твой_бот`
- `Команда /start от пользователя id=... username=...` — с твоим Telegram ID;
- `Неизвестная команда: /погода`.

Время в начале каждой строки — **московское**, сверь с часами на телефоне (допустимо
расхождение в пару секунд).

### 13. Останови бота

Вернись в окно, где бот работает, и нажми **Ctrl+C**.

**Должно получиться:** появляются строки `Получен Ctrl+C, выключаемся` и `Бот остановлен`,
после чего снова доступна обычная строка ввода. Красного текста и слова `Traceback` быть
не должно.

## Часть 4. Что будет, если ошибиться в токене

Здесь мы специально ломаем настройки, чтобы убедиться: бот ругается по-человечески,
а не вываливает простыню ошибок. После проверки всё вернём назад.

### 14. Пустой и неправильный токен

1. Открой настройки: `notepad .env`
2. Сотри токен, оставь строку `BOT_TOKEN=` пустой. Сохрани, закрой.
3. Выполни `python -m app`.

**Должно получиться ровно это, одной строкой:**

```
Ошибка: Не найден BOT_TOKEN. Скопируйте .env.example в .env и впишите токен от @BotFather.
```

Слова `Traceback`, `File "..."`, `line 42` появляться **не должны**.

4. Теперь открой `.env` снова и впиши заведомо неправильный токен: `BOT_TOKEN=абракадабра`.
   Сохрани, закрой. Выполни `python -m app` ещё раз.

**Должно получиться:** две строки — `ERROR app: Бот аварийно остановлен` и

```
Ошибка: Telegram не принял BOT_TOKEN. Проверьте, что в .env вписан свежий токен от @BotFather целиком, без пробелов и кавычек.
```

Опять же без `Traceback` в окне. Главное здесь: бот не рухнул и подсказал, что чинить.

5. **Верни настоящий токен** обратно в `.env`, сохрани, запусти `python -m app` и убедись,
   что снова видна строка `Бот запущен: @твой_бот`. После этого можно остановить бота Ctrl+C.

## Часть 5. Если что-то пошло не так

### 15. Как передать проблему

Скопируй из PowerShell **весь текст ошибки целиком** (выдели мышкой → Enter копирует),
открой Claude Code в папке проекта командой `claude` и напиши:

```
Используй агента debugger. Этап 1, пункт N чек-листа. Вот что вывелось: <вставь текст>
```

Частые случаи и что они значат:

| Что видно в окне | Что делать |
|---|---|
| `python: команда не найдена` / `не является внутренней или внешней командой` | Python не установлен или не добавлен в PATH — вернись к `docs/SETUP_WINDOWS.md`, пункт 1 |
| `No module named aiogram` | не выполнен пункт 4 (или забыл включить `.venv` — строка не начинается с `(.venv)`) |
| `Не получилось достучаться до Telegram` | нет интернета, либо Telegram блокируется провайдером/VPN |
| `Telegram не принял BOT_TOKEN` | токен вписан не целиком, с пробелом или кавычками — перепроверь пункт 3 |
| Бот запустился, но на `/start` молчит | убедись, что открыт чат именно с твоим ботом (username из пункта 2), и что окно с ботом всё ещё открыто |

## Итог

Этап 1 принят, если выполнены пункты 5–13: тесты зелёные, `/start` и `/help` отвечают,
неизвестная команда получает подсказку, обычный текст игнорируется, лог пишется
с московским временем, а Ctrl+C останавливает бота без ошибок.
