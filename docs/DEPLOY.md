# Переезд бота на сервер

Пока бот жил на твоём компьютере: закрыл окно PowerShell — бот выключился, а утром
он должен разбудить. Сервер (VPS) — это компьютер, который работает круглосуточно
и никогда не выключается. Туда мы бота и переселим.

Проходить сверху вниз, один раз. Займёт примерно час, из них минут двадцать —
ожидание, пока сервер сам что-то скачивает.

Никакого «настройте окружение»: каждая команда написана целиком, её можно скопировать
и вставить. Под каждой командой написано, что она делает и что должно получиться.

---

## Три вещи, которые надо знать заранее

**1. Бот должен работать в одном экземпляре.** Пока он крутится и на твоём компьютере,
и на сервере, оба будут драться за одни и те же сообщения: Telegram отдаёт очередь
обновлений только кому-то одному. В логах появится ругань `Conflict: terminated by other
getUpdates request`, и оба бота начнут отвечать через раз. Поэтому **перед запуском
на сервере закрой окно PowerShell с ботом на своём компьютере** (или нажми в нём Ctrl+C).

**2. Токен, ключи и база остаются только у тебя.** В git и на GitHub они не уезжают:
секреты живут в файле `.env`, который мы создадим прямо на сервере руками.

**3. Ошибиться не страшно.** Всё, что мы делаем на сервере, легко переделать заново.
Единственное, что стоит беречь, — файл базы `data/bot.db` с твоими настройками
и заметками; ради него в конце мы настроим автоматические копии.

## Часть 1. Подключиться к серверу

### 1. Что такое SSH

SSH — это способ управлять чужим компьютером из своего чёрного окна с командами.
Ты пишешь команду у себя, она выполняется на сервере, ответ печатается у тебя.
Ничего дополнительно устанавливать не надо: в Windows 10 и 11 SSH уже встроен.

Тебе нужны три вещи от провайдера, у которого ты арендовал сервер (обычно приходят
письмом сразу после оплаты):

- **IP-адрес** — четыре числа через точку, например `95.31.14.207`;
- **имя пользователя** — чаще всего `root`, иногда `ubuntu`;
- **пароль** (или ключ, если провайдер предложил загрузить ключ — тогда пароль не спросят).

### 2. Подключиться

Открой на своём компьютере PowerShell (клавиша Win → набрать `powershell` → Enter)
и выполни, подставив свои имя пользователя и IP:

```powershell
ssh root@95.31.14.207
```

`ssh` — программа подключения, `root` — имя пользователя на сервере,
после `@` — адрес сервера.

**При самом первом подключении** появится вопрос вида:

```
The authenticity of host '95.31.14.207' can't be established.
ED25519 key fingerprint is SHA256:xxxxxxxxxxxxxxxxxxxxxxxxxxx.
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

Это не ошибка. Компьютер говорит: «я вижу этот сервер впервые, точно к нему подключаемся?».
Напиши целиком `yes` и нажми Enter (просто `y` не подойдёт).

Потом попросит пароль:

```
root@95.31.14.207's password:
```

Вставь пароль (правой кнопкой мыши) и нажми Enter. **Пароль не отображается никак** —
ни точками, ни звёздочками, строка остаётся пустой. Это нормально, так задумано, просто
вставляй и жми Enter.

**Должно получиться:** приглашение сменилось на что-то вроде
`root@vps12345:~#`. Всё, что ты теперь печатаешь, выполняется на сервере.

> Альтернатива: программа PuTTY. Она делает то же самое, просто с окошком вместо команды.
> Ставить её не нужно — встроенного `ssh` достаточно.

> **Если ты зашёл не под `root`, а под другим пользователем** (например `ubuntu`),
> то ко всем командам с `apt` и `docker` дальше нужно приписывать спереди `sudo `
> (это «выполнить от имени администратора»), например: `sudo apt update`.
> Пароль он спросит один раз.

### 3. Обновить систему

```
apt update && apt upgrade -y
```

`apt` — это установщик программ в Ubuntu (аналог «Установить приложение» в Windows).
`apt update` обновляет список доступных программ, `apt upgrade -y` доустанавливает
свежие версии уже установленных, `-y` заранее отвечает «да» на все вопросы.

Займёт 1–3 минуты, побегут строки — это нормально.

Если посреди процесса появится синий экран с вопросом про перезапуск сервисов —
нажми Enter (выбран вариант «Ok»).

## Часть 2. Установить программы на сервер

### 4. Docker

Docker — это «коробка» для программы. Внутри коробки лежит нужная версия Python
и все библиотеки, поэтому боту всё равно, что установлено на самом сервере: он везде
запускается одинаково. Нам это даёт две вещи: не надо вручную ставить Python и venv,
и бот сам поднимается после перезагрузки сервера.

Устанавливаем официальным способом — скриптом с сайта docker.com:

```
curl -fsSL https://get.docker.com -o get-docker.sh
```

`curl` скачивает файл по ссылке, `-o get-docker.sh` — сохранить его под таким именем.
Ключи `-fsSL` означают «молча, без прогресс-бара, идти за переадресациями, ругнуться
при ошибке». Сам скрипт — официальный, его рекомендует Docker в своей документации.

```
sh get-docker.sh
```

Запускает скачанный скрипт: он сам определит, что у тебя Ubuntu 24.04, подключит
официальный репозиторий Docker и всё установит. Это самая долгая команда во всей
инструкции — 2–5 минут, экран будет активно писать строки.

Проверка:

```
docker --version
```

**Должно получиться:** строка вида `Docker version 27.x.x, build ...`.

```
docker compose version
```

**Должно получиться:** строка вида `Docker Compose version v2.x.x`.

`docker compose` (через пробел, не через дефис) — это дополнение к Docker, которое умеет
запускать программу по описанию из файла `docker-compose.yml`. Оно ставится вместе с
Docker автоматически, отдельно ничего делать не надо. Если эта команда ругается
`docker: 'compose' is not a docker command` — напиши об этом Claude Code, не гадай.

Скачанный скрипт больше не нужен:

```
rm get-docker.sh
```

### 5. git и sqlite3

```
apt install -y git sqlite3
```

Ставит сразу две программы: `git` — чтобы скачать код бота с GitHub и потом обновлять его,
`sqlite3` — чтобы делать резервные копии базы (пункт 15). `-y` — заранее «да».

Если они уже стоят, команда просто напишет `git is already the newest version` — это тоже
успех, ничего страшного.

## Часть 3. Положить бота на сервер

### 6. Скачать код

```
git clone https://github.com/e1ova00/tg-schedule-bot.git
```

`git clone` скачивает репозиторий (папку проекта вместе с историей изменений) с GitHub
в текущую папку сервера.

> **Про ветку.** Если код бота лежит не в основной ветке `main`, а в отдельной
> (у веток бывают имена вида `claude/stage-1-project-...`), то команда другая —
> с добавкой `-b` и именем ветки:
>
> ```
> git clone -b ИМЯ_ВЕТКИ https://github.com/e1ova00/tg-schedule-bot.git
> ```
>
> Какую именно ветку клонировать — спроси у Claude Code перед деплоем:
> «в какой ветке лежит актуальный код бота и что писать в git clone». Не угадывай:
> скачаешь не ту ветку — получишь бота без половины этапов.

Если репозиторий приватный, git спросит имя пользователя GitHub и пароль. Обычный пароль
не подойдёт, нужен токен GitHub — если дошло до этого, скажи Claude Code:
«репозиторий приватный, git на сервере просит логин», он подскажет, что делать.

**Должно получиться:** строки `Cloning into 'tg-schedule-bot'...` и в конце
`Resolving deltas: 100% ... done.`

Заходим в скачанную папку:

```
cd tg-schedule-bot
```

`cd` — «перейти в папку». Все следующие команды выполняются **изнутри этой папки**.
Если ты потом отключишься и подключишься заново — надо будет снова выполнить
`cd tg-schedule-bot`.

Проверим, что всё на месте:

```
ls
```

**Должно получиться:** в списке видно `app`, `data`, `docs`, `scripts`,
`docker-compose.yml`, `Dockerfile`, `requirements.txt`.

### 7. Создать файл `.env` с токеном и ключами

Секретов в скачанном коде нет — их надо вписать здесь, на сервере, руками.
Сначала делаем копию файла-образца:

```
cp .env.example .env
```

`cp` — «скопировать»: из файла-образца `.env.example` делаем настоящий файл настроек `.env`.

Теперь открываем его в текстовом редакторе:

```
nano .env
```

`nano` — простейший редактор прямо в чёрном окне. Мышь в нём не работает,
перемещаться по тексту нужно стрелками на клавиатуре.

Что вписать (значения бери из своего `.env` на компьютере — открой его в Блокноте
и скопируй оттуда):

- `BOT_TOKEN=` — токен от @BotFather, тот же самый, что дома;
- `DGIS_API_KEY=` — ключ 2ГИС (или `ORS_API_KEY=`, если используешь запасной маршрутизатор);
- `ALLOWED_USER_IDS=` — Telegram ID тех, кому можно пользоваться ботом, через запятую;
- `TELEGRAM_PROXY_URL=` — **оставь пустым** (см. врезку ниже).

Остальные строки (`ALARM_PLANNING_TIME`, `TZ`, `DB_PATH` и прочие) не трогай,
там уже правильные значения.

**Про прокси — важно.** Дома ты, возможно, вписывал `TELEGRAM_PROXY_URL`, потому что
Telegram открывается только через VPN. **На сервере этой строки быть не должно:**
адрес вида `socks5://127.0.0.1:10808` означает «прокси на этом же компьютере», а на
сервере такой программы нет — бот будет стучаться в пустоту и не запустится.
Порядок такой: **сначала запускаем без прокси**. Если сервер стоит за границей или
у провайдера прямой доступ к Telegram — всё заработает сразу, и это самый частый случай.
Если в логах будет `TelegramNetworkError` и «не получилось достучаться до Telegram» —
значит, этому серверу тоже нужен обходной путь, и это уже отдельная история
(настройка VPN на самом сервере): напиши об этом Claude Code.

Как сохранить и выйти из nano:

1. **Ctrl+O** — сохранить (внизу спросит имя файла — просто нажми **Enter**);
2. **Ctrl+X** — выйти из редактора.

(Внизу экрана nano подсказки написаны как `^O Write Out` — значок `^` и означает Ctrl.)

Проверить, что записалось:

```
cat .env
```

`cat` печатает содержимое файла на экран. Убедись, что в строке `BOT_TOKEN=` стоит
твой токен — без пробелов, без кавычек, всё в одну строку.

### 8. Разрешить боту писать в папки с базой и логами

```
mkdir -p data logs backups && chown -R 1000:1000 data logs
```

`mkdir -p` создаёт папки (если их нет): `data` — база, `logs` — логи, `backups` — резервные
копии. `chown -R 1000:1000 data logs` отдаёт две из них пользователю с номером 1000 —
именно под этим номером бот работает внутри своей коробки-контейнера. Без этой команды
бот запустится от имени «чужого» пользователя и не сможет создать файл базы, а в логах
будет невнятное `unable to open database file`.

Эту команду достаточно выполнить один раз.

## Часть 4. Запуск

### 9. Выключить бота на своём компьютере

Ещё раз, потому что это самая частая ошибка: **найди на своём компьютере окно PowerShell,
в котором крутится бот, и нажми в нём Ctrl+C** (или просто закрой окно). Двух ботов
с одним токеном Telegram не терпит.

### 10. Собрать и запустить

```
docker compose up -d --build
```

Одна команда делает всё: `--build` — собирает коробку с ботом (скачивает Python 3.12,
ставит библиотеки из `requirements.txt`, кладёт внутрь код), `up` — запускает,
`-d` — «в фоне», то есть бот продолжит работать после того, как ты закроешь SSH.

Первый запуск идёт 2–5 минут и печатает много технических строк — это нормально.

**Должно получиться:** в конце строки вида

```
 ✔ Container tg-schedule-bot  Started
```

### 11. Проверить, что бот жив

```
docker compose ps
```

Показывает список запущенных контейнеров.

**Должно получиться:** одна строка `tg-schedule-bot`, а в колонке `STATUS` —
`Up 30 seconds` (или другое время). Если там `Restarting` или `Exited` — бот падает,
иди в пункт 19.

```
docker compose logs -f
```

Показывает лог бота — то же самое, что раньше бежало в окне PowerShell.
`-f` значит «продолжать показывать новые строки по мере появления».

**Должно получиться:** знакомые строки

```
Бот запущен: @имя_твоего_бота (id=...)
Планировщик будильников запущен, пересчёт каждый день в 05:00 по Москве
Планировщик заметок запущен, пересчёт каждый день в 05:00 по Москве
```

Обрати внимание на время в начале каждой строки — оно должно совпадать с московским,
а не отставать на три часа. Часовой пояс задан в `docker-compose.yml` жёстко.

**Как выйти из просмотра логов: Ctrl+C.** Это останавливает только показ строк на экране,
**сам бот продолжает работать**. Проверить можно тем же `docker compose ps`.

### 12. Проверить в Telegram

Напиши боту `/start`, потом `/today`, потом `/preview`. Отвечает — переезд состоялся.

Настройки и заметки на сервер не переехали: база `data/bot.db` осталась на твоём
компьютере, а на сервере создана новая, пустая. Проще всего пройти `/start` заново
и ответить на четыре вопроса онбординга — это минута.

> Если очень хочется перенести старую базу с компьютера — не копируй файл поверх
> работающего бота, это ломает базу. Скажи Claude Code: «хочу перенести базу
> с компьютера на сервер», он даст правильный порядок команд.

### 13. Отключиться от сервера

```
exit
```

Закрывает SSH-сессию. **Бот при этом не выключается** — он работает в фоне на сервере
и переживёт даже перезагрузку сервера (за это отвечает строка `restart: unless-stopped`
в `docker-compose.yml`). Можешь выключать свой компьютер.

## Часть 5. Резервные копии базы

В базе лежат твои настройки (адрес, время на сборы) и все заметки. Файл маленький,
копию можно снимать хоть каждый день.

### 14. Разрешить запуск скриптов

```
chmod +x scripts/backup_db.sh scripts/deploy.sh
```

`chmod +x` помечает файлы как «исполняемые», то есть их разрешено запускать.

### 15. Проверить копию руками

```
bash scripts/backup_db.sh
```

**Должно получиться:** строка вида
`2026-09-07 03:00:12 копия готова: /root/tg-schedule-bot/backups/bot-2026-09-07-0300.db`

Скрипт не просто копирует файл: он просит саму SQLite сделать согласованный снимок
(`.backup`). Обычный `cp` мог бы скопировать базу ровно в момент записи и дать битую копию.
Последние 14 копий хранятся, всё, что старше, удаляется само.

Посмотреть, что получилось:

```
ls -lh backups
```

`ls -lh` показывает файлы с размером в понятном виде (килобайты, мегабайты).

### 16. Настроить автоматический запуск каждую ночь

cron — это встроенный будильник самого сервера: он умеет запускать команды по расписанию.
Открываем его список задач:

```
crontab -e
```

При первом запуске спросит, каким редактором править, — выбирай `1` (nano) и Enter.

Спустись стрелкой в самый низ файла (под все строки с `#`) и добавь одну строку:

```
0 3 * * * /bin/bash /root/tg-schedule-bot/scripts/backup_db.sh >> /root/tg-schedule-bot/logs/backup.log 2>&1
```

Расшифровка: `0 3 * * *` — «в 0 минут 3-го часа, каждый день, каждый месяц, каждый день
недели», то есть каждую ночь в 3:00. Дальше — что запускать. Хвост
`>> ... /logs/backup.log 2>&1` складывает весь вывод (и обычный, и ошибки) в файл,
чтобы потом можно было посмотреть, отработали копии или нет.

Сохранить и выйти — как в nano: **Ctrl+O**, **Enter**, **Ctrl+X**.

**Должно получиться:** строка `crontab: installing new crontab`.

> Если ты заходил на сервер не под `root`, путь другой. Узнать его: выполни `pwd`
> внутри папки проекта — она напечатает полный путь (например `/home/ubuntu/tg-schedule-bot`),
> его и подставь в строку вместо `/root/tg-schedule-bot`.
>
> Ещё: cron работает по времени сервера, но сам скрипт именует копии по московскому
> времени, так что путаницы в названиях не будет.

Проверить через сутки:

```
cat /root/tg-schedule-bot/logs/backup.log
```

### 17. Скачать копию к себе на компьютер (по желанию)

Выполняется **на своём компьютере**, в PowerShell, а не на сервере:

```powershell
scp root@95.31.14.207:/root/tg-schedule-bot/backups/*.db C:\Users\ИМЯ\Desktop\
```

`scp` — копирование файлов по тому же SSH. Слева — что копируем (с сервера),
справа — куда (папка на твоём компьютере). Подставь свой IP и своё имя пользователя Windows.

## Часть 6. Повседневные команды

Все они выполняются на сервере, изнутри папки проекта. То есть сначала:

```powershell
ssh root@95.31.14.207
```

```
cd tg-schedule-bot
```

### 18. Шпаргалка

| Что нужно | Команда | Пояснение |
|---|---|---|
| Посмотреть, работает ли бот | `docker compose ps` | в колонке STATUS должно быть `Up ...` |
| Посмотреть лог | `docker compose logs -f` | выход из просмотра — Ctrl+C, бот при этом живёт |
| Последние 50 строк лога | `docker compose logs --tail 50` | без ожидания новых строк |
| Перезапустить бота | `docker compose restart` | если он завис, но код не менялся |
| Остановить бота | `docker compose down` | база и логи остаются на месте |
| Включить обратно | `docker compose up -d` | без `--build`, если код не менялся |
| Обновить бота новой версией | `bash scripts/deploy.sh` | см. пункт 20 |
| Сделать копию базы прямо сейчас | `bash scripts/backup_db.sh` | |
| Место на диске | `df -h` | если вдруг кончилось |

### 19. Как остановить бота и не потерять базу

```
docker compose down
```

Останавливает и удаляет контейнер. **База данных при этом не удаляется**: файлы
`data/bot.db` и логи лежат в папке проекта на самом сервере, а контейнер только смотрит
в них (за это отвечают строки `volumes:` в `docker-compose.yml`). Можно удалить контейнер,
пересобрать его с нуля десять раз — настройки и заметки останутся.

Включить обратно:

```
docker compose up -d
```

### 20. Как обновить бота, когда в проекте появились изменения

Ты правишь код на своём компьютере через Claude Code, коммитишь и отправляешь на GitHub
(`git push`). Дальше на сервере одна команда:

```
bash scripts/deploy.sh
```

Скрипт по шагам: забирает свежий код с GitHub, пересобирает коробку, перезапускает бота,
подчищает мусор от старых сборок и показывает последние строки лога. База не трогается.

Если скрипт остановится на словах `Your local changes would be overwritten` — значит,
на сервере кто-то правил файлы руками. Не борись с этим сам, скопируй сообщение
в Claude Code.

## Часть 7. Если что-то не так

### 21. Первым делом — лог

```
docker compose logs --tail 100
```

Показывает последние 100 строк. Почти всегда причина видна там открытым текстом,
по-русски.

Ещё бот пишет собственный подробный лог в файл — он же виден и с сервера:

```
tail -n 100 logs/bot.log
```

### 22. Частые ситуации

**`STATUS: Restarting` в `docker compose ps`** — бот падает сразу после старта
и Docker поднимает его снова по кругу. Смотри лог (пункт 21), причина в последних строках.

**`Telegram не принял BOT_TOKEN`** — в `.env` попал неверный токен, лишний пробел
или кавычки. Открой `nano .env`, поправь, сохрани и выполни `docker compose up -d`.

**`TelegramNetworkError` / «не получилось достучаться до Telegram»** — у сервера нет
доступа к Telegram. Проверь, что `TELEGRAM_PROXY_URL` в `.env` **пустой** (домашний адрес
прокси на сервере не работает). Если пустой и всё равно не подключается — сообщи
Claude Code, нужен обходной путь для самого сервера.

**`Conflict: terminated by other getUpdates request`** — где-то работает второй экземпляр
бота с тем же токеном. Скорее всего, на твоём компьютере осталось открытым окно
PowerShell с `python -m app`. Закрой его.

**`unable to open database file` / `readonly database`** — не выполнена команда из пункта 8.
Выполни её и перезапусти бота:

```
chown -R 1000:1000 data logs && docker compose restart
```

**Бот не разбудил утром** — проверь, что вчера он был `Up` весь день (`docker compose ps`),
и посмотри `/preview` в Telegram: он показывает, во сколько бот собирается будить и почему.
В логе за нужное утро ищи строки со словом «будильник».

### 23. Что скопировать в Claude Code, если не разобрался

Не пересказывай своими словами. Скопируй в чат целиком:

1. команду, которую вводил;
2. весь текст, который сервер написал в ответ;
3. вывод `docker compose ps`;
4. вывод `docker compose logs --tail 50`.

И напиши: `Используй агента debugger. Бот на сервере, вот что происходит: <вставь всё это>`.

Токен и ключи из `.env` в чат вставлять не нужно — они там не помогут, а светить их лишний раз
не стоит.
