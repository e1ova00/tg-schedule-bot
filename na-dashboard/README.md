# N.A. — Fitness & Wellbeing Dashboard

N.A. — это персональный дашборд для тренировок, восстановления, самочувствия и питания. Это одностраничное приложение (SPA) на **чистом JavaScript ES6+** с ООП-архитектурой, без фреймворков и без backend. Все данные хранятся в `localStorage` браузера.

Учебный проект. Он показывает ООП (инкапсуляцию, наследование, полиморфизм), ES6-модули, работу с DOM, Fetch API, `AbortController`, корректный `destroy()`, визуализацию данных и доступность (accessibility).

> ⚠️ **Дисклеймер.** N.A. не является медицинским сервисом. Приложение не ставит диагнозов и не даёт медицинских рекомендаций. Расчёты фаз цикла — календарные и ориентировочные, это не метод контрацепции. Приложение не измеряет и не оценивает уровень гормонов. Наблюдения строятся только на собственных записях пользователя и показывают корреляции, а не причины.

## 1. Основные возможности

- **Onboarding** — полноэкранный мастер из 5 шагов: пол, базовые данные, цель, образ жизни, режим. Профиль можно изменить в любой момент.
- **5 разделов SPA** без перезагрузки страницы: Сегодня · Тренировки · Прогресс · Самочувствие · Питание.
- **«Сегодня»** — персональная карточка Daily Insight, работающая по правилам (rule-based), три кольца прогресса (Активность / Восстановление / Питание) и пользовательская сетка виджетов.
- **Dashboard** в каждом разделе. Виджеты можно:
  - добавлять и удалять (с подтверждением);
  - сворачивать и разворачивать;
  - менять размер S / M / L;
  - переставлять перетаскиванием (drag-and-drop) **или кнопками ↑ ↓**.

  Раскладка сохраняется.
- **8 типов виджетов** (у каждого экземпляра независимое состояние):

| Виджет | Что умеет |
|---|---|
| `TrainingWidget` | Старт по шаблону (Lower / Upper / Full Body или свой), упражнения, подходы (вес, повторы, RPE), заметка, таймер, сохранение. Определяет PR («Новый PR — Ягодичный мост: 100 кг»). Позволяет создавать свои упражнения и сохранять шаблоны |
| `ProgressWidget` | Графики Chart.js: силовые (макс. вес / объём / расчётный 1RM), замеры тела (вес, талия, бёдра, грудь, бедро, рука, свой замер), кардио (длительность / дистанция / пульс / интенсивность) |
| `MoodWidget` | Записи «Сейчас» и «День в целом», слайдер «Очень плохо ↔ Очень хорошо», факторы влияния, заметка, график за 30 дней |
| `RecoveryWidget` | Утренний check-in и прозрачный «Индекс восстановления 0–100» с раскладкой по компонентам |
| `BiologicalRhythmWidget` | Для женщин — календарный трекинг цикла и ориентировочная фаза. Для мужчин — суточный контекст и ручной ввод лабораторных показателей без интерпретации |
| `NutritionWidget` | Пользовательские цели КБЖУ, дневник по дням, вода, поиск продуктов в **Open Food Facts** |
| `SupplementsWidget` | Добавки с расписанием (утро / день / вечер / своё время) и частотой, отметка «Принято сегодня», «Регулярность — 87%» за неделю или месяц |
| `ExerciseLibraryWidget` | Библиотека упражнений из **wger**: категории, поиск, детали, добавление в свою библиотеку или в текущую тренировку |

- **InsightEngine** — наблюдения по правилам: тренды силы, связь сна и восстановления с результатами, время суток, настроение и тренировки, фазы цикла. Также ищет **оптимальное окно тренировки**.
- **Демо-данные** — одна кнопка загружает около 7 недель истории «Анны, 24 года».
- **Удалить все данные** — с подтверждением.
- **Темы**: светлая (по умолчанию), тёмная, системная.

## 2. Технологии

HTML5 · CSS3 (Grid, Flexbox, custom properties, `color-mix`) · vanilla JavaScript ES2022 · ES6 Modules · Chart.js 4 (локальная копия в `vendor/`) · Fetch API · AbortController · localStorage · нативный `<dialog>`.

Фреймворков и сборщиков нет. Drag-and-drop реализован на нативном HTML5 DnD, без библиотек.

## 3. Архитектура

```
main.js ──► StorageService ◄── все компоненты читают/пишут данные только через него
   │        ThemeManager, InsightEngine, WgerService, FoodService, Toast, Modal
   │
   ├─► WidgetRegistry  (тип → класс; 8 регистраций)
   │
   └─► Router (hash) ──► SectionView ──► Dashboard ──► UIComponent[] (виджеты)
                              └─► DailyInsightCard, ActivityRings, InsightsPanel
```

- **Поток данных.** Виджет пишет в `StorageService`. Хранилище генерирует событие `change` с ключом. Все компоненты, подписанные на этот ключ, перерисовываются через `watchStorage()`. Например, после сохранения тренировки обновляются Daily Insight, кольца и графики.
- **События** обрабатываются через делегирование. На корневой элемент компонента вешается по одному слушателю на каждый тип события. Элементы внутри помечены атрибутами `data-action`, `data-form`, `data-field`. Поэтому повторные перерисовки не плодят слушателей.
- **Связь виджета с дашбордом** идёт через всплывающее событие `component:request`. Виджет не знает о Dashboard, а Dashboard не знает внутренностей виджета.

## 4. ООП в проекте

### UIComponent — базовый абстрактный класс
`js/core/UIComponent.js` отвечает за общий жизненный цикл компонента.

- **Свойства:** `id`, `title`, `size`, `element`, `isMinimized`, `settings`, `services`. Приватные (`#`) реестры слушателей, таймеров, интервалов, `AbortController`-ов, графиков и дочерних компонентов.
- **Методы:** `render()`, `renderBody()` (абстрактный), `mount()`, `refresh()`, `minimize()`, `restore()`, `setSize()`, `destroy()`, `addEventListenerWithCleanup()`, `setTimeout` / `setInterval` с учётом очистки, `startRequest()` / `abortRequests()`, `registerChart()` / `queueChart()`, `addChild()`, `toJSON()`.
- Создать `new UIComponent()` напрямую нельзя: конструктор бросает `TypeError`.

**`destroy()` гарантированно:**
1. вызывает хук `onDestroy()` наследника;
2. уничтожает дочерние компоненты;
3. отменяет все незавершённые `fetch` через `AbortController`;
4. очищает `setTimeout` и `setInterval`;
5. уничтожает экземпляры Chart.js;
6. снимает все зарегистрированные слушатели;
7. удаляет DOM.

### Наследование
Все 8 виджетов, а также `FoodSearch` (встроенный дочерний компонент), `DailyInsightCard`, `ActivityRings` и `InsightsPanel` наследуются от `UIComponent`. Они переопределяют `renderBody()` и обработчики `onAction` / `onSubmit` / `onInput` / `onChange`. Компоненты без «карточки» переопределяют `renderFrame()`.

### Инкапсуляция
Состояние хранится в приватных полях: `#state`, `#value`, `#factors`, `#selected` и т. п. Хранилище отдаёт копии данных (`structuredClone`), поэтому изменить кэш снаружи нельзя. `Dashboard.widgets` возвращает копию массива. Прямых вызовов `localStorage.getItem` вне `StorageService` нет.

### Полиморфизм
`Dashboard` работает с любым виджетом через общий интерфейс: `mount`, `destroy`, `toJSON`, `setPosition`. Router работает с любым разделом через `mount` / `destroy`. Каждый виджет по-своему реализует `renderBody()`.

### Dashboard
`js/core/Dashboard.js` — коллекция активных виджетов одного раздела. Методы: `addWidget(widgetType)`, `removeWidget(widgetId)`, `moveWidget(id, toIndex)`, `render()`, `mount()`, `saveLayout()`, `loadLayout()`, `destroy()`.

Конкретные классы создаёт `WidgetRegistry`. Чтобы добавить новый тип виджета, нужно написать класс и добавить одну строку `.register(NewWidget)` в `main.js`. Сам Dashboard при этом не меняется — это принцип открытости/закрытости.

## 6. Используемые API

Оба API публичные и **не требуют ключей**. Запросы идут напрямую из браузера.

| API | Где используется | Эндпоинты |
|---|---|---|
| [wger](https://wger.de/api/v2/) | `ExerciseLibraryWidget` | `GET /api/v2/exercisecategory/`, `GET /api/v2/exerciseinfo/?category=&limit=&offset=` |
| [Open Food Facts](https://world.openfoodfacts.org/) | `NutritionWidget` → `FoodSearch` | `GET /cgi/search.pl?search_terms=…&json=1&fields=…` (поиск), `GET /api/v2/product/{штрихкод}.json` |

**Обязательные состояния.** У обоих API-компонентов есть явные состояния `idle → loading → success | empty | error`. Их отображает класс `AsyncView`; в состоянии ошибки есть кнопка «Повторить».

**Отмена запросов.** `startRequest(key)` создаёт новый `AbortController` и отменяет предыдущий запрос того же канала. Например, при быстрой смене категории в wger или при новом поиске продукта. `destroy()` отменяет текущий запрос. `AbortError` пользователю не показывается.

**Безопасность данных API.** Данные API считаются недоверенными: типы и диапазоны проверяются (`safeString`, `safeNumber`), а в DOM всё выводится только через `textContent`. HTML-описания из wger превращаются в обычный текст через `DOMParser`, без вставки разметки. Если API недоступен, остальное приложение продолжает работать.

## 7. Ограничения API

- **Open Food Facts:** полнотекстовый поиск ограничен примерно 10 запросами в минуту. Поэтому поиск запускается только по кнопке или Enter, а не на каждый символ. Данные краудсорсинговые: у части продуктов нет КБЖУ, такие продукты нельзя выбрать. Поиск может отвечать медленно (таймаут — 20 с).
- **wger:** большинство описаний на английском, переводы на русский есть не у всех упражнений. Поиск идёт по уже загруженным упражнениям (по 40 на страницу, есть кнопка «Показать ещё»). Категории подгружаются из API, а при недоступности берутся из встроенного списка.
- Оба сервиса бесплатные и не дают гарантий доступности.

cd na-dashboard

Сборка и установка зависимостей не нужны. Для быстрого знакомства на первом экране нажмите **«Посмотреть с демо-данными»**.

## 11. Accessibility

- Семантическая разметка: `nav`, `main`, `article`, `section`, `header`, иерархия заголовков h1 → h2 → h3. Есть skip-link «Перейти к содержимому».
- Всё управление доступно с клавиатуры. Видимый `:focus-visible`. При смене раздела фокус переходит на заголовок раздела.
- У всех кнопок-иконок есть `aria-label`. У полей есть `<label for>`, у ошибок — `aria-invalid` и `aria-describedby`.
- **Альтернатива drag-and-drop:** кнопки ↑ ↓ в заголовке каждого виджета. После перемещения фокус остаётся на кнопке, а позиция озвучивается через `aria-live`.
- Модальные окна построены на нативном `<dialog>`: фокус удерживается внутри окна, закрываются по Esc, после закрытия фокус возвращается на кнопку, которая открыла окно.
- Шкалы 1–5 сделаны на радиокнопках (переключаются стрелками), слайдер настроения — на `input[type=range]` с `aria-valuetext`. Переключатели используют `aria-pressed`, свёртка — `aria-expanded`.
- У графиков `role="img"` и текстовое описание данных. Числа в кольцах продублированы для скринридеров.
- Контраст текста ≥ 4.5:1: для текста используются отдельные «ink»-оттенки категорий.
- `prefers-reduced-motion` отключает анимации CSS и Chart.js.

## 12. Ограничения проекта

- Данные живут только в одном браузере. Синхронизации, аккаунтов и экспорта нет — это сознательно вне scope.
- Наблюдения InsightEngine — простая статистика по небольшой выборке: средние, сравнение групп, корреляция Пирсона. Для оптимального окна нужно минимум 8 тренировок; при нехватке данных приложение честно об этом пишет.
- «Эффективность» тренировки — это относительная величина: расчётный 1RM в сравнении со средним из трёх предыдущих результатов в том же упражнении. Это упрощённая модель.
- Расчётный 1RM считается по формуле Эпли — это оценка. Фазы цикла рассчитываются по календарю, без учёта физиологии.
- Перетаскивание мышью реализовано через HTML5 DnD. На сенсорных экранах используются кнопки ↑ ↓.
- В тренировке нельзя редактировать уже добавленный подход — его можно удалить и добавить заново.

## 13. Использование ИИ

При разработке использовался AI-помощник (Claude Code). Он применялся для:

- **проектирования архитектуры** — разбиения на модули, иерархии `UIComponent` → виджеты, схемы «Storage → событие → перерисовка»;
- **генерации части boilerplate-кода** — DOM-хелперов, разметки форм, CSS-токенов светлой и тёмной темы;
- **рефакторинга** — например, вынесения отложенной отрисовки графиков (`queueChart`) из трёх виджетов в базовый класс;
- **поиска потенциальных ошибок** — утечек слушателей, неотменённых запросов, неуничтоженных графиков, затенения глобальных имён;
- **улучшения accessibility** — фокуса после перемещения и удаления виджетов, `aria`-атрибутов, кнопочной альтернативы drag-and-drop;
- **документирования** — комментариев в коде и этого README.

Требования, сценарии, формулы (индекс восстановления, правила наблюдений) и итоговые решения определял и проверял автор. Сгенерированный код просматривался вручную и проверялся в браузере: onboarding, добавление, удаление и перемещение виджетов, сохранение после перезагрузки, тренировки и PR, оба API во всех четырёх состояниях (с подменой ответов сети), отмена запросов, уничтожение графиков, темы, мобильная вёрстка.
