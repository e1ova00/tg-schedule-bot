# Telegram-бот «Расписание 4-МД-4»

Умный бот-будильник для одной студенческой группы СПбГУПТД (ИИТА, 4 курс, 7 семестр).
Пользователей — 2–3 человека. Задача бота: не показывать расписание, а **вовремя будить и
не давать забыть про дедлайны**.

## Правила работы для агента

- Язык кода — Python 3.12. Все тексты для пользователя — на русском.
- Пользователь **не программист**. Любую команду, которую надо выполнить в терминале,
  пиши полностью и объясняй, что она делает. Никаких «настройте окружение» без деталей.
- Работаем **по этапам из `docs/PLAN.md`**. Не начинай следующий этап, пока текущий не
  прошёл критерии приёмки. После каждого этапа — короткий отчёт: что сделано, что проверить руками.
- Не выдумывай данные. Расписание берётся только из `data/schedule_4md4.json`.
- Никаких секретов в коде. Всё через `.env` (см. `.env.example`).
- Пиши маленькие модули с понятными именами. Каждая функция бизнес-логики должна быть
  тестируемой без Telegram и без сети.

## Стек

| Слой | Выбор | Почему |
|---|---|---|
| Telegram | `aiogram` 3.x | async, много примеров на русском |
| Хранилище | SQLite через `aiosqlite` | 2–3 пользователя, ноль настройки |
| Планировщик | `APScheduler` (AsyncIOScheduler) | утренние будильники и напоминания за 24 ч |
| Маршруты | 2ГИС Routing API | авто с пробками + общественный транспорт, российский, есть пробный ключ |
| Часовой пояс | `Europe/Moscow` жёстко | сервер почти наверняка в UTC |

Запасной маршрутизатор, если ключ 2ГИС не дадут: OpenRouteService (бесплатно, **без пробок**) —
тогда базовое время умножается на коэффициент часа пик из конфига.

## Данные расписания

`data/schedule_4md4.json` уже сгенерирован из Excel скриптом `scripts/parse_schedule.py`.
Перегенерировать нужно только если деканат выпустит новый файл.

Одно занятие:

```json
{
  "id": "L123",
  "weekday": 2,              // 1 = понедельник ... 6 = суббота
  "start": "11:40", "end": "13:05",
  "parity": "odd",           // odd = числитель, even = знаменатель, both = каждую неделю
  "subject": "Администрирование вычислительных систем и сетей",
  "kind": "Пр",
  "teacher": "Зверев В.В.",
  "building": "ул. Садовая, д. 54",
  "room": "С 407",
  "is_remote": false
}
```

Всего 21 занятие, из них 7 дистанционных, 3 разных корпуса.

## Бизнес-правила (здесь легче всего ошибиться)

### 1. Числитель / знаменатель

Неделя, в которую попало **1 сентября 2026**, — числитель.
Якорь: понедельник `2026-08-31` = числитель, дальше чередование.

```python
ANCHOR = date(2026, 8, 31)
def week_parity(d: date) -> str:
    monday = d - timedelta(days=d.weekday())
    return "odd" if ((monday - ANCHOR).days // 7) % 2 == 0 else "even"
```

Занятие идёт в день `d`, если `lesson.parity in ("both", week_parity(d))`.

Контрольные значения для тестов:

| Дата | День | Чётность |
|---|---|---|
| 2026-09-01 | Вт | odd (числитель) |
| 2026-09-07 | Пн | even |
| 2026-09-14 | Пн | odd |
| 2026-09-21 | Пн | even |
| 2026-10-01 | Чт | odd |

### 2. Пустые дни — норма, а не ошибка

У группы регулярно бывают дни без пар:

- **числитель:** четверг пустой
- **знаменатель:** пятница и суббота пустые
- **понедельник всегда полностью дистанционный** → будильник не отправляется никогда

Бот обязан корректно отвечать «сегодня пар нет» и молчать вместо будильника.

### 3. Корпусов три, а не один

Вознесенский 46, Садовая 54, Большая Морская 18. Ехать надо **до корпуса первой очной пары
конкретного дня**, а не «до университета». Во вторник по знаменателю первая пара на Садовой,
по числителю — на Вознесенском: адрес назначения зависит от чётности недели.

Координаты корпусов геокодируются один раз при первом запуске и кэшируются в БД.

### 4. Будильник

Отправляется утром в день, где есть хотя бы одна **очная** пара.

```
время_выхода = начало_первой_очной_пары − время_в_пути − запас
время_будильника = время_выхода − время_на_сборы
```

`время_в_пути` считается в момент отправки, с учётом пробок, от адреса пользователя до нужного
корпуса выбранным транспортом. `время_на_сборы` и `запас` пользователь задаёт при онбординге.

Если первая пара дня дистанционная, а очная только третьей — будильник считается по очной,
но в тексте это проговаривается.

### 5. Заметки

Привязка — к **конкретному занятию** (`lesson.id` + дата), не к предмету.

- После окончания пары бот спрашивает: есть ли домашка или заметки.
- Кнопка «Заметки» → выбор периода → список.
- За 24 часа до пары, к которой есть незакрытая заметка: напоминание с кнопками «Сделал / Не сделал».
  «Сделал» → заметка закрывается. «Не сделал» → мягкое подталкивание, напоминание повторится утром.

Тон напоминаний — дружелюбный, без давления и без морализаторства.

## Определение готовности

Этап считается сделанным, когда: код запускается без ошибок, есть тесты на бизнес-логику
этапа, они проходят, и в отчёте написано, что именно проверить руками в Telegram.
